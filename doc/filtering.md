# Pipeline overview -- with a focus on filtering steps

## 1. Locus definition — BLAST of probes against the reference

Probes are BLASTed against the reference genome and BLAST hits are filtered:

| Step                | Setting                     | Value                                           |
| ------------------- | --------------------------- | ----------------------------------------------- |
| BLAST               | `--top_n_query`             | 5 hits per probe                                |
| BLAST               | `--pct_id`                  | ≥ 90%                                           |
| BLAST               | `--pct_qcov` (HSP-based)    | ≥ 80%                                           |
| `01d_filter-loci.R` | Percent identity (`pident`) | ≥ 95% for at least one hit                      |
| `01d_filter-loci.R` | Query coverage (`qcovhsp`)  | ≥ 90% for at least one hit                      |
| `01d_filter-loci.R` | Multi-hit probes            | Removed entirely (probes with > 1 retained hit) |
| `01d_filter-loci.R` | Hits per probe              | First hit kept                                  |
| BED output          | Buffer around each hit      | 300 bp on each side (`buffer_size`)             |

- Result: 2,000 probes → 1,936 with BLAST hits → 1,819 loci.

## 2. Genotype calling and consensus generation

A) **Read processing and variant calling** --
   uses the nf-core Sarek pipeline, run per sample, with the following settings:

| Step               | Tool                 | Setting                                                         |
| ------------------ | -------------------- | --------------------------------------------------------------- |
| Trimming           | fastp 0.24.0         | Adapter trimming, remove reads <15 bp, otherwise fastp defaults |
| Mapping            | bwa-mem 0.7.18       | Default settings                                                |
| Duplicates         | GATK4 MarkDuplicates | Duplicates marked - these are then ignored by freebayes         |
| Base recalibration | —                    | Skipped (`skip_tools: baserecalibrator`)                        |
| Calling regions    | —                    | Restricted to the probe BED (`intervals`)                       |
| Variant calling    | freebayes 1.3.10     | `--report-monomorphic`, otherwise default                       |

- Freebayes: because `--report-monomorphic` is set via the config,
  the Sarek's pipeline defaults are overridden by the Freebayes program defaults.
  This means that `--min-alternate-fraction 0.05` is used instead of 0.1,
  but I think that's OK.

B) **Genotype filtering and consensus generation**:

Eight bcftools steps:

| Step                | Setting                 | Value                               | Effect                                                    |
| ------------------- | ----------------------- | ----------------------------------- | --------------------------------------------------------- |
| 0. Block splitting  | —                       | —                                   | Multi-bp monomorphic records split into one per base      |
| 1. Genotype quality | `--filter_expr`         | `FORMAT/DP < 5 \|\| FORMAT/GQ < 20` | Genotypes below depth/GQ set to missing (`./.`)           |
| 2. Site quality     | `--min_qual`            | 30                                  | Genotypes at low-QUAL variant sites set to missing        |
| 3. Indel proximity  | `--snp_gap`             | 5 bp                                | Genotypes at SNPs within 5 bp of an indel set to missing  |
| 4. Normalization    | `bcftools norm`         | `--multiallelics -any --atomize`    | Splits multiallelics and MNVs, left-aligns indels         |
| 5. Indels           | `bcftools view`         | `-V indels`                         | Indels removed; SNPs only                                 |
| 6. Allele balance   | `--min_ab` / `--max_ab` | 0.25 / 0.75                         | Skewed heterozygote genotypes set to missing              |
| 7. Multiallelics    | `--drop_multiallelic`   | `true`                              | Positions left with >1 record after step 4 are removed    |

Step 0 exists because FreeBayes occasionally merges a run of invariant positions
into a single record (REF several bp long, ALT `.`), which can span past the end of
the per-region reference slice given to `bcftools consensus` and crash it.

The consensus sequences are then generated by `bcftools consensus` where heterozygous
sites get IUPAC ambiguity codes, and missing/absent genotypes become `N`.

--------------------------------------------------------------------------------

## 3. Pivot, trim, and filter consensus sequences

A) **Pivot to locus-centric FASTA files**

B) **Per-locus trimming** with ClipKit to remove terminal `N` stretches caused by the buffers:

   - Only alignment ends are trimmed (`--ends_only`)
   - A terminal column is trimmed if >25% of sequences have `N` at that position

C) **Sample and locus filtering** -- `scripts/03c_filter-loci.sh`, applied in this order:

| Step                       | Parameter            | Value  | Effect                                                           |
| -------------------------- | -------------------- | ------ | ---------------------------------------------------------------- |
| 1. A priori sample removal | `--remove_samples`   | -      | Samples flagged as contaminated in `metadata/metadata-final.tsv` |
| 2. Per-sample missingness  | `max_missing_sample` | 0.1    | Samples with mean >10% `N` across all loci removed               |
| 3. Minimum locus length    | `min_locus_length`   | 150 bp | Post-trimming alignment length                                   |
| 4. Per-locus missingness   | `max_missing_locus`  | 0.2    | Loci with mean >20% `N` across retained samples removed          |

Per-locus missingness in steps 3-4 is recomputed after sample removal in steps 1-2,
so the locus filter is based only on retained samples.
VCFs are then subset to the retained samples and loci.

--------------------------------------------------------------------------------

## 4. Excess-heterozygosity locus filter

`scripts/04b_filter-excess-het.sh`, run after the per-locus genotype counts from
`scripts/04a_qc-vcf.sh`. Targets paralogous copies collapsing onto one reference
locus, which is the failure mode that most distorts heterozygosity estimates.

Per-locus het density = `total het calls / (n_samples * locus length)`.
Loci above `max_het_pctile` (default: 99th percentile) are dropped from both the
FASTA and VCF sets. `scripts/05a_prep-qc-tables.R` excludes the same blacklist,
since the count tables in `stats/vcf` are built before this filter.
