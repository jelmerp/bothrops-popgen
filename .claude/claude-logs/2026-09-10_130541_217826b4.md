## The one that affects results

`bcftools view -v snps` counts **records**, but a record whose genotype the filters set to missing still carries its ALT allele — it becomes `N` in the consensus, not a variant. Measured on a real output VCF:

```
SNP records:            18270
ALT genotypes:          12755   <- actual variable sites
hom-ref:                  392
missing (become N):      5123 (28%)
```

So the logged `Variable sites` figure — the one [run/1_main.md:120](run/1_main.md#L120) greps out of the logs — and the per-region counts in `*_snp-counts-per-region.tsv` were ~43% too high. Both now use `-i 'GT="alt"'`. Nothing downstream reads that TSV yet, so changing the column was safe, but the numbers will differ from your existing results.

## Bugs

- **`bcftools stats` clobbered across samples.** It wrote to a fixed `$outdir/vcf_stats.txt`, and the runner submits one job per sample into a shared `-o`. I confirmed the single stale file sitting in `results/geno/consensus/sample_init/`. Now `stats/${sample_id}_vcf-stats.txt`.
- **`bcftools index` had no `-f`** — re-runs fail on the existing index.
- **Reference `.fai`** is now required up front; concurrent jobs would otherwise race to build it.
- **The lookup-file "atomic create" block was dead code.** `mv` always overwrites, so the "only succeeds if file doesn't exist" comment was wrong and the wait loops it guarded were unreachable (with an infinite-loop path if they ever were reached). A same-filesystem rename is already atomic and all jobs write identical content, so it's now a plain rename.
- **`--more_opts` was parsed and documented but never used** — now passed to `bcftools consensus`.
- `zgrep -vc "^#"` would abort under `set -e` on an empty VCF → `bcftools view -H | wc -l`. Same for `grep -m5 ">"` on an empty FASTA.
- Missing `$TOOL_BINARY` prefixes on `bcftools stats`, the `bcftools view` in the process substitution, and `seqkit`.
- 5 CPUs requested, never used — `--threads` now goes to the compressing steps.
- Template conformance: `set -euo pipefail` at the top, `check_val` in arg parsing (caught `--sample_id --ref foo` in testing), `log_provenance`, absolute `LOG_DIR`.
- DESCRIPTION said "five steps" for seven, and omitted normalization and multiallelic dropping.

I checked the `${qual_expr:+-e "$qual_expr" ...}` idiom since unquoted expansions with embedded quotes usually word-split — bash honors the inner quotes here, so it was already correct.
