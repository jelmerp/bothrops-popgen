## What happened

`check_val` was undefined because the Bash function script never got loaded properly.

[02b_bcftools-consensus.sh](scripts/02b_bcftools-consensus.sh) resolves the function script as `$script_dir/../dev/bash_functions.sh` → `/fs/ess/PAS1533/users/jelmer/dev/bash_functions.sh`, which doesn't exist (the submodule is now `core-scripts/`, not `mcic-scripts/`). So it fell through to the download branch, which `wget`s `bash_functions.sh` into the **working directory**.

All 191 jobs started within the same second (15:09:52). Two of them (14420547, 14420548) printed "downloading from GitHub..." and ran `wget -q ... -O bash_functions.sh` concurrently into the shared cwd. The other jobs tested `[[ -f bash_functions.sh ]]` — 32 of them hit the window where the file existed but was still being written, sourced a truncated file, got no functions, and died at the first `check_val` (exit 127). The remaining 159 sourced a complete file and finished fine.

The pattern confirms it: exactly 32 output files are 83 bytes with that single error, and exactly 32 samples are missing a consensus FASTA (159 of 191 present).

## Fix applied

Rewrote `source_function_script()` in [01a](scripts/01a_blastdb.sh), [01b](scripts/01b_blast.sh), [02a](scripts/02a_nfc-sarek.sh), [02b](scripts/02b_bcftools-consensus.sh) and [03b](scripts/03b_clipkit.sh):

- Searches `../dev/`, then `../core-scripts/dev/`, then the working dir for a non-empty copy — so on this repo it now finds `core-scripts/dev/bash_functions.sh` and never downloads.
