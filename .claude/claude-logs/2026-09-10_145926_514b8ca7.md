## Leave it as is

I tested the assumption on three samples. The hom-ref calls that would get masked are, with rare exceptions, good calls.

**Cost of the mask** (sample `P0021_FG_I1549`, representative):

| | |
|---|---|
| Target space | 2.22 Mb (1,819 regions) |
| Currently called bases | 1.79 Mb |
| Indel spans ±5 bp, merged | 35.5 kb — 1.6% of target |
| Inside those windows: hom-ref bases now emitted as reference | **15,980** (0.9% of all called bases) |
| Inside those windows: ALT bases already blanked by `--SnpGap` | 1,201 |

**Are those 15,980 bases actually untrustworthy?** Mostly not:

| Hom-ref calls | mean DP | mean GQ | mean non-ref read fraction | sites ≥10% non-ref reads |
|---|---|---|---|---|
| Inside indel windows | 39.8 | 156.3 | 0.0014 | **0.46%** (73) |
| Outside | 41.9 | 157.3 | 0.0001 | 0.02% (352) |

Depth and GQ are indistinguishable. There *is* a real enrichment of noise — 14× on non-ref read fraction, 23× on the ≥10% tail — but the absolute number is ~50–75 suspect calls per sample (0.28–0.48% inside windows across the three samples tested, consistently). Masking the whole window discards roughly **200 good bases for every dubious one removed**.

Two more reasons not to bother:

- FreeBayes is haplotype-based and realigns reads within its haplotype windows, so the pileup-style misalignment artifact that motivates `SnpGap` is much weaker here than for GATK UG / mpileup. `--SnpGap 5` is already conservative — it discards ~8% of this sample's ALT genotypes, and ALT calls are 8.6× enriched near indels partly because SNPs and indels genuinely co-segregate on divergent haplotypes.
- The worst form of this bias is already handled. Bases inside a hom-alt deletion span become `N` via `--absent N`; only 22 positions per sample slip through with a reference base.

## If you do want to close the gap, do it differently

A positional mask is the wrong instrument — it targets location rather than evidence, and the evidence is what separates the bad calls. A better trade is to extend the existing allele-balance filter (step 6) to hom-ref genotypes: blank a hom-ref call whose non-reference read fraction exceeds ~0.1. That costs ~425 genotypes per sample (0.02%), and it catches the dubious calls *outside* indel windows too — 352 of the 425 are outside, so the positional mask would miss them entirely.

One implementation caveat: `FMT/AO` is `Number=A`, and on monomorphic records (`ALT="."`) it may be missing rather than 0, so the expression needs the same explicit indexing and a missing-value guard as the current `ab_expr` — worth testing on one sample before adopting.
