## Bugs

**`z_class` was being read as all-NA.** In `sample-by-locus-stats.tsv` the column is NA for every autosomal locus (851k of 881k rows), so readr guessed logical from the leading rows and turned every real class into NA — 30,000 parsing problems behind a warning that scrolls past. Nothing used the column yet, so it broke nothing visible. Explicit `col_types` added in both 05b and 05c.

**`geno_pct` is NA where a locus is uncalled in a sample** (`n_called == 0`, 897 rows). 05c already passed `na.rm = TRUE`; 05b did not, so one uncalled pair made a whole locus or sample mean NA. This one mattered: the per-sample heterozygosity correlations were being computed over the biased subset that survived, giving r(depth, het) = **−0.30** and r(missingness, het) = **+0.27**, which I had written up as a possible contamination signature. With `na.rm = TRUE` they are **+0.10** and **−0.12** — both near zero, so heterozygosity is *not* set by coverage and the 05c comparisons are not confounded. The report now says that instead.

**The excess-het table showed NA for exactly the loci it was about.** It pulled 04e's `n_sites_scored`, which only exists for the final locus set — so the four dropped excess-het loci had NA there. It wants 04c's `n_sites_het_scored`.
