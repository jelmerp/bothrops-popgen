[doc/filtering.md](doc/filtering.md) now has sections 7–9 with the analysis. Answers:

## 1. The QUAL filter — no, applying it would have destroyed the data

Not a missed opportunity; using the unfiltered VCF was correct. Because calling used `--report-monomorphic`, the VCFs are ~99% invariant sites, and freebayes gives those QUAL ≈ 0 (QUAL = P(site is polymorphic)). For one sample:

| Record type | n | QUAL > 30 |
|---|---|---|
| Has ALT | 19,768 | 16,645 (84.2%) |
| Monomorphic | 2,389,990 | **0 (0.0%)** |

The filtered file keeps 16,645 of 2,409,758 records. Passing that to `bcftools consensus --absent N` would turn every reference position into `N`.

A QUAL filter is still worth having, but restricted to ALT records and setting genotypes missing rather than dropping records: `bcftools filter -e 'ALT!="." && QUAL<30' --set-GTs .`. 14.2% of ALT sites are below QUAL 30.

## 2. Sarek's freebayes defaults — no, but they're both missing something important

`--min-mapping-quality 1` is the freebayes program default, so that override changed nothing. `--min-alternate-fraction` went 0.1 → 0.05; 0.05 is the more standard germline choice and affects few calls (0.6% of hets have AB < 0.10). The override is fine.

**But neither passes `--genotype-qualities`** — which leads to:

## 3. Yes, but first: the GQ ≥ 20 filter never did anything

`FORMAT/GQ` is `.` for every genotype in these VCFs, because freebayes only emits GQ with `--genotype-qualities`. In a bcftools expression, comparison against a missing value is false:

```
bcftools view -H -i 'FORMAT/GQ < 20' <raw>.vcf.gz | wc -l   # 0
bcftools view -H -i 'FORMAT/DP < 5'  <raw>.vcf.gz | wc -l   # 698,776
```

So the consensus sequences are **depth-filtered only** (DP ≥ 5), which at 30–70× mean depth is permissive — 11.6% of retained genotypes sit at DP 5–9. Fixing this needs re-calling with `--genotype-qualities` added to `config/nfc-sarek.config`.

On the other two filters you asked about:

- **Allele balance** — worth adding, but not naively. 19.5% of het calls have AB > 0.75, and 98.6% of the AB ≥ 0.90 ones are split multiallelics where `bcftools norm -m -any` sent the other ALT's reads to a separate record. Restricted to clean biallelic records (`AO+RO == DP`), 92.1% fall in 0.25–0.75, so a filter there costs 7.9% of het calls. Worth it given `07c_genotype-counts.qmd` reports het counts.
- **Per-site depth** — low priority. Maxima are only 5–8× the median, no repeat-collapse tail. If added it must be per-sample: mean depth ranges 31–73× across five samples, so a global cutoff would be wrong.

The higher-yield paralogy screen is per-locus excess heterozygosity, which needs no re-calling: het density is median 0.0015/bp, p99 0.0054, max 0.0217 — L1970, L1813 and L1839 sit 8–14× the median and look like collapsed paralogs. That's ~1–2% of loci.

Priority order in section 9: re-call with `--genotype-qualities`, then the excess-het locus filter, then allele balance, then QUAL-on-ALT-records, then optionally max depth.
