Yes — I'd set them to missing.

**Why the current behavior is wrong**

`bcftools filter --SnpGap` hard-filters: the record is dropped, so `bcftools consensus` falls back to the reference base ([02b_bcftools-consensus.sh:337](scripts/02b_bcftools-consensus.sh#L337)). That turns "we don't trust this call" into a positive hom-ref assertion. Consequences downstream:

- Reference bias: het and non-reference calls are the ones being erased, so heterozygosity is biased down and reference-allele frequency up — which matters given the excess-het locus filter and the genotype-count tables.
- Indels are sample-specific, so which sites get reverted differs per sample. A sample with an indel gets a fake ref base where a neighboring sample keeps its real ALT, and that shows up as a genuine difference in trees/distances rather than as missing data.
- N is already handled everywhere downstream (per-locus missingness filters, ClipKit, the QC tables); a wrong base is not.

The cost is more N, but it's bounded: `-g` only flags ALT-bearing SNP records, so you only lose positions that actually had a variant call within ±5 bp of an indel, not the whole window.

**Implementation**

`--SnpGap 5 -S .` does *not* work — I tested it, `--set-GTs` doesn't apply to `-g` failures and the records are still dropped. Two passes do:

```bash
bcftools filter --SnpGap "$snp_gap" -s SnpGap -m + -O u |
bcftools filter -e 'FILTER~"SnpGap"' --set-GTs . -O u |
```

Verified on a toy VCF: the flanking SNPs come out `./.` and the indel record passes through untouched.

**Two related inconsistencies**, if you want the stricter version

1. `-g` doesn't flag monomorphic records (confirmed by testing), so hom-ref positions inside the same ±5 bp window keep their reference base. If the reason for distrusting the window is alignment ambiguity around the indel, that reasoning applies to the ref calls too.
2. Discarding indels is right — the per-locus alignments need fixed-length sequences — but for a deletion, keeping the reference bases asserts the sample has bases it doesn't.

Both are fixed the same way: emit a per-sample BED of indel spans ±`snp_gap` and pass it to `bcftools consensus --mask ... --mask-with N`, instead of (or in addition to) the genotype-level filter. That's a bigger change and loses more data; the two-line filter fix above covers the main bias.

| ------------- | ------- | ---------- | ----- | -------- |

Two findings:

1. **There is no pile-up immediately next to indels** — 1–3 bp is *below* background. FreeBayes merges variants within its haplotype window into a single complex/MNV allele, so those SNPs are never emitted as separate records at all (hence the sharp step between 3 and 4 bp — that's the window edge, not biology). The BCFtools-call artefact you found on 2026-03-22 is genuinely gone, exactly as that entry predicted.

2. **The elevation at 4–30 bp is indistinguishable from the elevation at 51–200 bp**, and hasn't reached background by 200 bp. Same for the mild het excess. That's a regional effect — indels and SNPs both accumulate in variable/repetitive regions — not local misalignment. The curve has no shoulder, so no cutoff separates artefact from real variation.

What the window costs, now that it produces `N` instead of reference bases:

| `snp_gap` | % of variable sites blanked | sites/sample |
| --------- | --------------------------- | ------------ |
| 3         | 0.6%                        | ~71          |
| 5         | 1.5%                        | ~172         |
| **10**    | **3.8%**                    | **~434**     |
| 15        | 5.8%                        | ~669         |

**Recommendation: 5.** 10 bp discards ~3.8% of your variable sites at the same artefact-to-signal ratio as anywhere else in the locus — it isn't buying anything specific. 5 bp covers the edge of the FreeBayes haplotype window (where a boundary SNP could plausibly escape being absorbed into the complex allele) at ~1.5%. 0 would also be defensible, leaving it to the DP/GQ, QUAL and allele-balance filters.

One caveat: the >200 bp background includes other loci, so part of the 1.3× at 101–200 bp may be a between-locus difference rather than a within-locus gradient. It doesn't change the conclusion — what matters is that 4–30 bp looks like 51–200 bp.
